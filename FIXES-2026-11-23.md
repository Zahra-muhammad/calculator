# Fixes – 23 Nov 2026

Checked with all 360 tests, the type check, the production build,
`npm run check:single` (47/47) and a browser run that uses every control.

## Bugs fixed

| # | Problem | Fix |
|---|---------|-----|
| 1 | The **Imports** sheet was read as "notes", so VAT on imported services and goods was missing | New register type "Imports": services → Box 3 (reverse charge), goods → Box 6, and both → Box 10 as recoverable input VAT |
| 2 | A **car used for personal trips** was claimed | Input VAT on motor vehicles available for personal use, and on goods for employees' personal use, is blocked automatically (Executive Regulation Art. 53) |
| 3 | An invoice with **no supplier TRN** was still claimed | New treatment "Held: no valid tax invoice" (Art. 55). Staff switch it to Recoverable, with a reason, once a corrected invoice arrives |
| 4 | A **duplicate invoice** was counted twice | An exact repeat (same number, party, net and VAT) is left out and flagged HIGH. Tick "Count this line" if it really is a separate invoice |
| 5 | An invoice showing the **wrong VAT** (2,000 instead of 2,500) was counted as shown | Output VAT counted is 5% of the value; the difference is flagged. Input VAT counted is never more than 5% of net |
| 6 | There were no **VAT return boxes** | The VAT tab, Excel and PDF now show the full VAT201: Box 1a–1g by emirate, 3, 4, 5, 6, 8, 9, 10, 11, 12, 13 and 14 |
| 7 | A **VAT-only** file showed "Corporate tax due AED 0" and 16 CT questions | The header shows "VAT payable", and CT flags and profile counts are hidden until there is a trial balance |
| 8 | **Client name** took the whole READ ME sentence | It stops at the legal ending (LLC, FZE, Ltd…) |
| 9 | Export worked with **nothing loaded** (CT-client-no-period.xlsx) | Export says "Nothing to export yet" |
| 10 | RV-03 asked for VAT returns even when a **sales register** was uploaded | The sales register is used to reconcile revenue |
| 11 | Late payment label read "2 months, 51 days" | Now "51 days late = 2 months or part" |
| 13 | **Client name** was filled in by itself (e.g. "Desert Star Office Supplies LLC") and stayed for the next client | The name is never filled in. When a name is found in the file, a button "Use “…” from the file" fills it on click |
| 14 | Light/dark/auto theme button | Removed. The app is light only |
| 15 | Only some questions were yellow | Every field that still needs an answer is a yellow box: profile, accounts questions, PBT, period end, VAT reasons, exchange rate |
| 16 | Amounts in **another currency** were treated as AED | The currency in the sheet is detected (USD, SAR, EUR…). Amounts are converted to AED (USD 3.6725 and other pegged rates filled in; others must be typed). Staff can change the rate or click "Change to AED (Dhs)". No rate = HIGH flag. Excel and PDF show the currency and rate |
| 17 | SBR did not check that the business is a **UAE Resident Person** | A non-resident (permanent establishment or nexus, chosen under Deadlines → Who is registering?) is not eligible (Ministerial Decision 73/2023 Art. 2) |
| 18 | **Period start/end** not read from the company record | Answers next to labels are read ("Financial year start / end", "Tax period: 1 Jan 2025 to 31 Dec 2025"), as text or Excel dates |
| 19 | Legal form showed **Tax group member** for an LLC | The label "Tax group status" was read as the answer. Now only the answer next to it is read ("Not a member…" = No). Result: Mainland company |
| 20 | **Foreign income** showed Yes although the record says No | Same cause (the label "Foreign income / foreign branch" contains "branch"). Labels are never answers now |
| 21 | **PDFs** (auditor's report, director's confirmation, notes) were not accepted | PDFs are read on the computer (pdf.js, offline). Sentences are read with "not / no" inside the same clause ("not a member of a Corporate Tax group … and had no foreign branch" = No, No, No) |
| 22 | **Ownership change** not read from the director's confirmation | "There was no change in direct or indirect ownership" = No |
| 23 | SBR **refused** because the period end was missing | A missing period end now asks for it ("confirm first"), it does not refuse |
| 24 | Facts were not **cross-checked** | Every file's answers are compared. Same answer → filled, with "Same answer in N files". Different answers → left blank (yellow) with a HIGH flag naming each file and cell. Files naming a different company or TRN → HIGH flag "may belong to different clients" |
| 25 | A **VAT summary** with "Sales excl VAT" was not read as VAT returns | Read (TOTAL row skipped): revenue per VAT returns 1,508,000; the VAT note's explanation fills "Explanation of any difference" |
| 26 | Cell references said to be "one row off" | Checked: references come from Excel's own cell addresses. In the Harbourline record the TRN really is in **B4** (B3 is the client name). A new test opens every cited cell in every test workbook and checks it holds the value |
| 27 | False "No" for foreign income | "Foreign branch tax paid: Omani tax paid; certificate not included" was read as No because of "not". Now it means foreign tax WAS paid (= Yes) and certificates = No. A label only answers its own question |
| 28 | Losses question shown with no losses | "Losses after the ownership change" is only asked when losses are brought forward. It is never filled in from documents; until answered, cautious mode keeps the losses out (HIGH flag) |
| 29 | "A transfer of 25% of the Company's shares…" not read | Read as ownership change = Yes. "Operated a branch in Oman" read as foreign = Yes. "Certificate not attached" read as certificates = No |
| 12 | The file-type list had 10 confusing options and a VAT workbook showed as "Sales invoices" | Only two choices now: **Corporate tax** and **VAT**. A workbook with only VAT sheets is detected as VAT. Corporate tax also reads any VAT sheets in the same workbook; VAT reads only the VAT sheets |

Also new: VAT shown on a zero-rated/exempt sale is flagged; supply type and emirate columns are read;
VAT-only exports are named `VAT-…`.

## Not changed

No tax rate or threshold in `settings.ts` was changed. The SBR election still needs
"earlier periods ≤ AED 3M" and "not part of a group" answered before it gives AED 0 (by design).
Apportionment of input VAT for businesses with exempt sales is not built yet.
